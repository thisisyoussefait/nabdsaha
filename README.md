# نبض الصحة (Nabd Siha) — موقع الصحة واللياقة البدنية

موقع بمفهوم **Topical Authority**: صفحة أم (Pillar) هي `index.html` تشرح "الصحة واللياقة
البدنية" بشكل عام وتتفرّع منها 6 صفحات فرعية (Cluster) مترابطة داخلياً، كل واحدة تستهدف
مجموعة من الكلمات المفتاحية المتقاربة بدل تكرار نفس الصفحة لكل كلمة.

## اقتراح اسم الدومين

| الاسم | الفكرة |
|---|---|
| **nabdsaha.com** ⭐ (المُعتمد في هذا المشروع) | "نبض الصحة" — يربط بين رمز اللياقة (النبض) وبنية الموقع (Hub بمحاور مثل نبضات القلب). قصير، سهل النطق، متاح غالباً بامتداد `.com` و `.ma` |
| liyaqti.ma | "لياقتي" — بعد شخصي، مناسب لموقع بطابع خدماتي/كوتشينغ |
| sihatak.net | "صحتك" — مباشر وواضح |

## توزيع الكلمات المفتاحية على الصفحات (Silo Structure)

- `index.html` — الصحة واللياقة البدنية (عام) + الصحة و اللياقة البدنية
- `tarif.html` — تعريف الصحة واللياقة البدنية، الصحة واللياقة، الصحه واللياقه، اللياقه والصحه
- `ahamiya.html` — اهمية الصحة واللياقة البدنية، صحة ولياقة بدنية، صحه ولياقه بدنيه
- `bahth.html` — بحث الصحة واللياقة البدنية (وكل صيغه)، وحدة الصحة واللياقة البدنية
- `maqal.html` — مقال/موضوع عن الصحة واللياقة البدنية، الصحة واللياقة البدنية بحث
- `sabahak.html` — صباحك صحة ولياقة
- `calculator.html` — الخدمة (حاسبة اللياقة)

كل صفحة تحتوي على `<title>` و`meta description` فريدين، `canonical`، وروابط داخلية
(Related) نحو الصفحات المكمّلة — وهذا هو جوهر بناء Topical Authority.

## هيكل المشروع

```
site/
├── index.html, tarif.html, ahamiya.html, bahth.html,
│   maqal.html, sabahak.html, calculator.html   ← نسخة HTML/CSS/JS ثابتة (جاهزة للنشر مباشرة)
├── css/style.css        ← نظام تصميم موحّد (Design tokens)
├── js/main.js           ← منطق الخدمة (حاسبة BMI/السعرات) — يعمل محلياً 100%، بدون أي fetch
├── sitemap.xml
├── robots.txt
├── react-src/            ← نفس الموقع بنسخة React (Vite + react-router)
│   ├── src/App.jsx, src/pages/*.jsx, src/components/*
│   └── src/utils/fitness.js   ← نفس منطق الحساب، بدون أي استدعاء شبكي
└── backend/              ← Express اختياري (لا علاقة له بالخدمة نفسها)
    └── server.js         ← نقطة API وحيدة تجريبية: تسجيل بريد إلكتروني للنشرة
```

## ⚠️ ملاحظة مهمة بخصوص "الخدمة داخل الموقع بدون إرسال أي شيء"

حاسبة اللياقة (مؤشر كتلة الجسم BMI + الاحتياج اليومي من السعرات) **تُحسب بالكامل
داخل متصفح المستخدم** بلغة JavaScript، في كل من:
- النسخة الثابتة: `js/main.js`
- نسخة React: `react-src/src/utils/fitness.js`

لا يوجد أي `fetch` أو `XMLHttpRequest` أو اتصال بأي خادم داخل منطق الحساب — البيانات
التي يُدخلها المستخدم (العمر، الوزن، الطول...) لا تُرسل ولا تُخزَّن في أي مكان خارج الجهاز.

الباك-إند في `backend/` **منفصل تماماً** ومخصص فقط لوظيفة اختيارية مستقبلية
(اشتراك في نشرة بريدية)، وليس جزءاً من الخدمة المطلوبة.

## التشغيل

### النسخة الثابتة (HTML/CSS/JS)
افتح `index.html` مباشرة في المتصفح، أو انشرها على أي استضافة ثابتة (Netlify,
Vercel, GitHub Pages, cPanel...).

### نسخة React
```bash
cd react-src
npm install
npm run dev      # للتطوير المحلي
npm run build    # لإنتاج نسخة جاهزة للنشر (مجلد dist/)
```

### الباك-إند الاختياري
```bash
cd backend
npm install
npm start         # يشتغل على http://localhost:4000
```

## SEO — ما تم تطبيقه

- بنية Topical Authority (صفحة أم + صفحات فرعية مترابطة بروابط داخلية)
- `title` و`meta description` فريدين لكل صفحة، مبنيين على الكلمات المفتاحية المستهدفة
- `canonical` URL لكل صفحة، ووسوم Open Graph أساسية
- `sitemap.xml` يضم كل الصفحات مع أولويات (priority) منطقية
- `robots.txt` يسمح للزحف ويشير إلى `sitemap.xml`
- Schema.org (`WebSite`) في الصفحة الرئيسية
- عناوين H1/H2 منظمة هرمياً، وسحابة كلمات مفتاحية (kw-cloud) بصيغ الكتابة المختلفة
  (بدون حشو مفرط) في كل صفحة فرعية
- محتوى نصي حقيقي وكافٍ لكل صفحة (وليس صفحات فارغة تستهدف كلمة واحدة فقط)

## الخطوة التالية المقترحة

1. اشترِ الدومين المقترح واربطه باستضافة (Netlify/Vercel مجانية للبداية)
2. انشر النسخة الثابتة أولاً (أسرع للفهرسة من طرف Google)
3. سجّل الموقع في Google Search Console وأرسل `sitemap.xml`
4. أضف 2-3 مقالات جديدة شهرياً ضمن نفس البنية (silo) للحفاظ على نمو الترافيك
